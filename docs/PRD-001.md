# PRD-001: 영상물등급위원회의 비디오물 등급분류정보 조회

## 목적

- Open API 요청 -> 응답 수신 -> 사용할 수 있는 데이터 형태로 반환

---

## 범위

### 포함

- Open API 인증키 설정
- 영등위 API 호출
- 특정 업체의 등급분류 자료 조회
- 페이지 단위 조회
- API 응답 파싱
- 응답 데이터를 내부에서 사용할 수 있는 형태로 변환
- API 오류 및 네트워크 오류 처리
- fetch 로직 테스트

### 제외

- DB 저장
- 기존 데이터와 비교
- 데이터 동기화
- 스케줄링
- 사용자에게 제공할 API 엔드포인트
- 프론트엔드

---

## 흐름

```
업체 / 조회 조건
      ↓

Parsing

```

## 요구사항

### API 설정

API 호출에 필요한 설정을 환경변수로 관리한다.

```
ORS_API_KEY=...
ORS_API_BASE_URL=...
```

### 업체별 데이터 조회

특정 업체에 해당하는 비디오물 등급분류 정보를 조회할 수 있어야 한다.

예시:

```python
response = await client.fetch(
    company_name="업체명",
    page=1,
    page_size=100,
)
```

실제 요청 파라미터와 명칭은 영상물등급위원회 API 명세를 기준으로 구현한다.

### 페이지네이션

API가 페이지 단위로 데이터를 반환하므로 특정 페이지를 조회할 수 있어야 한다.

최소한 다음 값을 지정할 수 있도록 한다.

```
company_name
page
page_size
```

예:

```python
await client.fetch(
    company_name="업체명",
    page=2,
    page_size=100,
)
```

전체 페이지를 자동 조회하는 기능은 실제 사용 방식에 따라 별도의 작업으로 분리할 수 있다.

### 외부 API 명세

영상물등급위원회의 **비디오물 등급분류 정보 조회 API (`/video_search_v2`)**를 사용한다.

#### Endpoint

```text
/video_search_v2
```

#### 일일 트래픽

```text
1,000 requests/day
```

일일 호출 제한이 있으므로 불필요한 API 요청을 최소화한다.

#### Request Parameters

| Parameter | 설명 | 예시 |
|---|---|---|
| `serviceKey` | 공공데이터포털에서 발급받은 인증키 | URL Encoded 인증키 |
| `pageNo` | 페이지 번호 | `1` |
| `numOfRows` | 한 페이지 결과 수 | `3` |
| `title` | 비디오 제목 | `건즈앤로세스` |
| `rtNo` | 등급분류번호 | `2026-VF00848` |
| `aplcName` | 신청사명 | `주식회사 키노라이츠` |
| `prodcName` | 제작사명 검색어 | `LB Entertainment` |
| `stDate` | 등급분류 기간 시작일 (`YYYYMMDD`) | `20260201` |
| `edDate` | 등급분류 기간 종료일 (`YYYYMMDD`) | `20260228` |

#### 업체 조회

현재 서비스에서 특정 업체의 데이터를 조회할 때는 `aplcName`을 주요 검색 조건으로 사용한다.

예:

```text
aplcName=주식회사 키노라이츠
```

따라서 애플리케이션 내부의 `company_name`은 API 요청 시 `aplcName`으로 변환한다.

```python
await client.fetch(
    company_name="주식회사 키노라이츠",
    page=1,
    page_size=100,
)
```

실제 API 요청:

```text
serviceKey={ORS_API_KEY}
&pageNo=1
&numOfRows=100
&aplcName=주식회사 키노라이츠
```

#### 내부 파라미터와 API 파라미터 매핑

| 내부 | ORS API |
|---|---|
| `company_name` | `aplcName` |
| `page` | `pageNo` |
| `page_size` | `numOfRows` |
| `title` | `title` |
| `rating_number` | `rtNo` |
| `producer_name` | `prodcName` |
| `start_date` | `stDate` |
| `end_date` | `edDate` |

외부 API의 파라미터 이름을 애플리케이션의 다른 영역에서 직접 사용하지 않고 `OrsClient` 내부에서 변환한다.

#### 날짜 조건

`stDate`, `edDate`를 이용하여 등급분류 기간을 기준으로 데이터를 조회할 수 있다.

날짜 형식은 다음과 같다.

```text
YYYYMMDD
```

예:

```text
stDate=20260201
edDate=20260228
```

향후 주기적인 데이터 동기화를 구현할 경우 전체 데이터를 반복 조회하지 않고 **등급분류 기간을 이용한 증분 조회가 가능한지 검토한다.**

> 참고: 현재 feature에서는 데이터 동기화를 구현하지 않으며, 날짜 조건을 이용한 조회 기능까지만 고려한다.

## 응답 처리

API에서 받은 원본 응답을 애플리케이션 코드에서 직접 다루지 않도록 한다.

```
API Response
    ↓
Parser
    ↓
Internal Model
```

예:

```python
class VideoRating:
    title: str
    company_name: str | None
    rating: str | None
    classification_date: date | None
    classification_number: str | None
```

구체적인 필드는 실제 API 응답 스키마를 확인한 후 결정한다.

외부 API의 필드명이 애플리케이션 전체에 퍼지지 않도록 API 응답과 내부 모델 사이에 변환 계층을 둔다.

---

## 오류 처리

다음 상황을 정상적으로 처리해야 한다.

- HTTP 4xx
- HTTP 5xx
- Connection Error
- Timeout
- API 인증 실패
- API가 오류 코드를 반환한 경우
- 예상하지 못한 응답
- 응답 파싱 실패

외부 HTTP 라이브러리의 예외를 그대로 노출하기보다 ORS Client 수준의 예외로 변환한다.

예:

```python
class OrsError(Exception):
    pass


class OrsRequestError(OrsError):
    pass


class OrsResponseError(OrsError):
    pass
```

## 예상 인터페이스

초기 구현에서는 API 호출 책임을 하나의 Client로 분리한다.

```python
class OrsClient:
    async def fetch(
        self,
        company_name: str,
        page: int = 1,
        page_size: int = 100,
    ) -> OrsResponse: ...
```

`fetch()`의 책임은 다음까지로 제한한다.

```
request 생성
    ↓
HTTP 요청
    ↓
response validation
    ↓
parsing
    ↓
OrsResponse 반환
```

## 테스트

외부 API에 대한 실제 호출 없이 주요 동작을 검증할 수 있어야 한다.

필수 테스트 케이스:

- 정상적으로 한 건을 가져오는 경우
- 여러 건을 가져오는 경우
- 결과가 없는 경우
- 특정 페이지 조회
- 일부 필드가 없는 응답
- HTTP 4xx
- HTTP 5xx
- Timeout
- API 오류 응답
- 잘못된 응답 형식

실제 영상물등급위원회 API를 호출하는 테스트가 필요하다면 unit test와 별도의 integration test로 관리한다.

## 완료 조건

- 환경변수에서 API Key를 읽을 수 있다.
- 영상물등급위원회 API에 요청할 수 있다.
- 특정 업체를 조건으로 데이터를 조회할 수 있다.
- 페이지 번호와 페이지 크기를 지정할 수 있다.
- 정상 응답을 내부 데이터 모델로 변환할 수 있다.
- 조회 결과가 없는 경우를 처리할 수 있다.
- HTTP 오류를 처리할 수 있다.
- Timeout 및 네트워크 오류를 처리할 수 있다.
- API 자체 오류 응답을 처리할 수 있다.
- 주요 동작에 대한 unit test가 작성되어 있다.

## 완료 결과

이 feature가 완료되면 애플리케이션의 다른 코드에서는 외부 API의 세부 구현을 알 필요 없이 다음과 같은 방식으로 데이터를 가져올 수 있어야 한다.

```python
client = OrsClient()

result = await client.fetch(
    company_name="업체명",
    page=1,
    page_size=100,
)
```

이 feature에서는 **가져온 데이터를 어떻게 저장하거나 활용할지는 결정하지 않는다.**
